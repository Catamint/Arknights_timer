# 明日方舟游戏数据显示工具：新手使用教程

本教程适用于桌面版 `ArknightsTimeline.exe`，内容包括模拟器与 ADB 连接、首次寻址、敌人监控、操作记录、随机数追踪和 JSON 导出。程序主界面顶部的“新手教程”按钮会直接打开本文件；它位于“选择 ADB”左侧。

项目地址：[Tim23333/Arknights_timer](https://github.com/Tim23333/Arknights_timer)

## 零、五分钟快速开始

第一次使用时，推荐按下面的顺序配置：

1. 启动 **MuMu 模拟器 12**，在模拟器设置中开启 ADB 调试和 Root 权限，然后重启模拟器；
2. 启动《明日方舟》，再打开 `ArknightsTimeline.exe`；
3. 点击顶部“选择 ADB”，选择 MuMu 自带的 `adb.exe`，并选择与 MAA“连接地址”一致的在线设备；
4. 展开“更多自定义选项”，勾选“启用自动寻址”；
5. 进入目标关卡，确认“游戏时间”和“逻辑帧”开始变化；
6. 点击“扫描关卡及操作”，用于记录部署、手动技能和撤退；
7. 点击敌人区域的“开始扫描”，等待进入实时监控；
8. 需要查看战斗随机序列时，再点击“扫描随机数”；
9. 经常连续打多局时，可以开启“自动检测关卡变化并自动刷新插件状态”。

只查看敌人数据时，第 6 步和第 8 步可以跳过。自动寻址无法使用时，再按照第四节使用独立寻址工具。

## 一、开始前的准备

1. 将 `ArknightsTimeline.exe` 放进一个可正常读写的独立文件夹，不要直接在压缩包中运行。
2. 启动 Android 模拟器，并在模拟器中启动《明日方舟》。
3. 推荐先使用“启用自动寻址”，它通过 Root ADB 读取游戏内时间，不要求 Windows 管理员权限。只有使用备用的“打开寻址工具”读取 Windows 模拟器进程时，才需要以管理员身份运行。
4. 首次使用建议选择 **MuMu 模拟器 12**。这是完整功能当前主要适配和验证的环境。
5. 扫描期间保持游戏关卡和模拟器运行，不要关闭游戏、切换账号或重启模拟器。

> MuMu 窗口最小化或失去焦点时，游戏可能自动暂停。此时数据停止变化属于模拟器行为，恢复到前台即可继续。

## 二、模拟器兼容性说明

本工具的功能分为两种读取方式，因此兼容范围并不完全相同。

| 功能 | 读取方式 | 兼容情况 |
| --- | --- | --- |
| 游戏时间、逻辑帧 | Root ADB 自动寻址；或 Windows 进程内存手动寻址 | MuMu 12 的自动寻址已验证；手动寻址已识别多个常见模拟器进程 |
| 敌人监控 | root ADB 读取 Android 游戏进程内存 | MuMu 12 已验证；其他模拟器满足条件时可尝试 |
| 操作记录 | root ADB 读取 `BattleLogger` | MuMu 12 已验证；其他模拟器满足条件时可尝试 |
| 随机数追踪 | root ADB 读取 arm64 IL2CPP 进程 | MuMu 12 已验证；其他模拟器满足条件时可尝试 |

其他模拟器要使用自动寻址、敌人、操作记录和随机数等 ADB 功能，必须同时满足：

- 游戏运行在 Android **arm64** 环境中；
- 模拟器的 ADB 可以执行 `adb root`；
- root ADB 能读取 `/proc/<游戏PID>/mem`；
- `adb devices` 能看到状态为 `device` 的模拟器；
- 可以找到模拟器自带的 `adb.exe`，或电脑已经安装 Android SDK Platform Tools。

因此，其他模拟器可以尝试，但不能直接写成“完整支持”。如果只需要时间和逻辑帧，也可以使用兼容范围更宽的 Windows 独立寻址工具；如果需要全部功能，优先使用 MuMu 12。

## 三、连接模拟器与 ADB

### MuMu 12

1. 先启动 MuMu 12，再启动《明日方舟》。
2. 打开主程序，点击顶部的“选择 ADB”。
3. 可以点击“自动探测运行中模拟器”，让程序查找 MuMu 自带的 `adb.exe` 和在线设备。
4. 如果没有自动找到，点击“浏览 adb.exe…”并选择 MuMu 安装目录中的：

   ```text
   MuMuPlayer-12.0\shell\adb.exe
   ```

   常见路径示例：

   ```text
   D:\Program Files\MuMu9\emulator\MuMuPlayer-12.0\shell\adb.exe
   ```

5. 在“设备地址”中选择与 MAA“连接地址”一致的设备，然后点击“使用此 ADB”。配置会保存到程序旁的 `enemy_adb_config.json`，后续一般不需要重复选择。

### 其他模拟器

手动选择该模拟器自己的 `adb.exe`。如果模拟器没有自动出现在设备列表中，需要先按照模拟器文档开启本地 ADB 调试，并连接它提供的端口。

可在 PowerShell 中进行基础检查：

```powershell
& "D:\模拟器目录\adb.exe" devices
& "D:\模拟器目录\adb.exe" root
& "D:\模拟器目录\adb.exe" shell pidof com.hypergryph.arknights
```

正常情况下：

- `devices` 能看到一台状态为 `device` 的设备；
- `root` 不会提示禁止以 root 运行；
- `pidof` 会返回一个数字形式的游戏进程 PID。

如果模拟器需要手动连接端口，可先执行：

```powershell
& "D:\模拟器目录\adb.exe" connect 127.0.0.1:模拟器端口
```

端口由模拟器决定，不同品牌和实例可能不同，应以模拟器的 ADB 设置或官方说明为准。

## 四、首次定位游戏时间和逻辑帧

### 推荐：自动寻址

1. 先完成第三节的 ADB 选择；
2. 展开主界面底部的“更多自定义选项”；
3. 勾选“启用自动寻址”；
4. 进入任意战斗关卡，等待提示“自动寻址成功，已启用 guest 时钟”；
5. 确认主界面的“游戏时间”和“逻辑帧”持续变化。

自动寻址会记住开关状态，并在下次启动时重新定位。游戏或模拟器重启后，程序会重新寻找当前有效地址，不应沿用旧进程中的地址。

### 备用：独立寻址工具

建议先完成时间与逻辑帧寻址，再使用操作记录。否则较早发生的操作可能无法补上精确逻辑帧，也就无法导出。

1. 进入普通作战 **0-1**，不建议使用演习作战。
2. 回到主程序，点击“打开寻址工具”。
3. 寻址工具会自动等待并识别当前模拟器进程。
4. 在关卡中等待费用到约 **11.5**，然后暂停游戏。
5. 在寻址工具中输入：

   ```text
   Min Value: 1
   Max Value: 2
   ```

6. 点击首次扫描。第一次需要扫描模拟器进程内存，耗时会比后续筛选长。
7. 回到游戏继续运行，费用到约 **12.5** 时再次暂停，输入：

   ```text
   Min Value: 2
   Max Value: 3
   ```

8. 点击“Next Scan”继续筛选。
9. 之后每增加约 1 点费用，就将范围整体加 1，例如 `3~4`、`4~5`，直到候选地址只剩 1 个。
10. 寻址成功后，地址会自动推送到主程序。确认主窗口的“游戏时间”和“逻辑帧”开始实时变化。

如果主界面没有立即更新，可点击“刷新游戏状态”。确认主界面正常显示后，寻址工具窗口可以关闭。

### 时间与帧地址何时需要重扫

当前时间地址只在本次运行中使用，没有保存为永久缓存。出现以下情况时通常需要重新寻址：

- 重启了模拟器或游戏进程；
- 游戏更新后内存布局变化；
- 主界面显示“—”、`Data Invalid` 或刷新失败；
- 切换到了另一个模拟器进程。

## 五、首次扫描与缓存

程序目录中可能出现以下文件：

| 文件 | 用途 |
| --- | --- |
| `enemy_adb_config.json` | 保存手动选择的 `adb.exe` 路径 |
| `enemy_cache.pkl` | 保存敌人列表与战斗控制器的地址链 |
| `ak_rng_cache.pkl` | 保存随机数引擎地址链 |

缓存只保存“地址怎么找”，不会保存或修改游戏数据。缓存每次使用前都会进行校验；游戏重启、模拟器重启或版本更新后，旧地址可能失效，此时需要重新扫描。

随机数缓存命中后通常可以跳过完整扫描并快速启动。敌人模块也会生成地址缓存，但当前桌面版点击“开始扫描”或“重新扫描”时会主动执行重新定位，因此仍可能等待一次完整扫描。操作记录目前按当前关卡定位，没有单独的持久化地址缓存。

不要把 `.pkl` 缓存复制到另一台电脑或另一个模拟器实例中使用。扫描异常时可以关闭程序，删除对应缓存文件后重新打开并扫描。

## 六、查看游戏时间、逻辑帧和倍速

完成时间寻址后，主界面左侧会显示：

- **游戏时间**：当前关卡内部计时，单位为秒；
- **逻辑帧**：游戏战斗逻辑使用的帧编号。

倍速状态来自 ADB 读取到的 `BattleController`。完成敌人监控或操作记录定位后，可以在对应状态栏看到当前战斗状态、战斗时间以及 `x1`、`x2` 等倍速信息。

如果游戏已经暂停、模拟器失去焦点或窗口被最小化，时间和数据可能暂时冻结。

## 七、使用敌人监控

1. 进入一个正常作战关卡。
2. 点击“开始扫描”。当前定位会从 `BattleController`、`Scheduler` 和 `UnitManager` 获取关卡与实时单位，场上暂时没有敌人时也可以开始。
3. 首次扫描通常需要约 **20～40 秒**；设备、关卡和堆大小不同会影响耗时。
4. 扫描期间不要结束关卡、切换账号或重启游戏。
5. 显示“定位完成”后，程序会自动进入实时监控。

敌人表格可显示名称、编号、血量、攻击、防御、法抗、移动速度、攻击速度、地图坐标、技能冷却和存活状态等信息。

“精确坐标”右侧的五个路径列会显示敌人的意图终点、当前主/额外/运行时路线、下一路点、下一检查点以及检查点秒数/帧数。路径数据必须与敌人状态属于同一逻辑帧；若游戏正在切换路线或检查点，列会短暂显示“同步重试”，不会继续展示上一帧路线。

- 点击“小数位设置”可调整不同数值的显示精度；
- 点击“显示列”可选择主表中显示哪些字段；
- 点击“列宽自适应”可按内容整理表格；
- 点击某个敌人行末的“详情”，可查看完整属性、状态、损伤条、Buff、关卡效果和技能信息；
- 进入新关卡或状态提示地址链失效时，点击“重新扫描”。

## 八、记录部署、技能与撤退操作

建议在关卡开始前先完成时间与逻辑帧寻址。

1. 进入需要记录的作战关卡。
2. 点击“扫描关卡及操作”。
3. 程序先识别当前关卡，再定位操作日志。快速路径约 **20 秒**，完整扫描可能需要 **1～2 分钟**。
4. 显示“监控中”后，正常进行游戏。
5. 每次部署、手动开启技能或撤退，都会追加到表格底部。

表格包括：

- 战斗时间；
- 逻辑帧；
- 操作类型；
- 干员名称；
- 部署朝向；
- 地图格子坐标；
- 附加信息。

注意事项：

- 自动开启的技能不是玩家操作，游戏的 `BattleLogger` 不会记录；
- 手动技能、部署和撤退会正常记录；
- 代理作战模式会直接显示完整代理序列，属于静态记录，不需要持续轮询；
- 进入新关卡后应重新点击“扫描关卡及操作”；
- 如果刚进关卡时定位失败，可以先部署一次干员，再重新扫描。

## 九、使用随机数追踪

1. 进入战斗关卡。
2. 点击“扫描随机数”。
3. 首次定位通常需要约 **15～30 秒**；缓存有效时可以更快完成。
4. 显示“监控中”后，界面会展示关键随机序列。

随机数区域包括：

- **未来预测**：下一次将使用的随机值位于最上方；
- **最近消耗**：游戏刚刚消耗过的关键随机值；
- **游标**：当前序列位置；
- **已消耗**和**消耗速率**；
- **预测数**：可设置为 1～500 发。

关键随机主要用于会影响战局的随机判定。如果当前场面没有发生暴击、闪避、概率天赋或其他随机判定，“最近消耗”暂时不变化属于正常现象。

进入新一局后服务会尝试检测随机数引擎变化并重新定位。如果长时间没有恢复，可点击“停止”，再点击“扫描随机数”。

## 十、导出操作记录

当前桌面界面的“导出 JSON”用于导出操作记录。

1. 在战斗前完成时间与逻辑帧寻址。
2. 点击“扫描关卡及操作”并等待进入监控状态。
3. 完成需要记录的部署、技能和撤退操作。
4. 点击“导出 JSON”。
5. 选择保存位置，程序会生成类似 `deploy_log_20260730_120000.json` 的文件。

如果提示有操作没有匹配到精确逻辑帧，说明时间/帧寻址完成得太晚，或对应帧已超出程序的短期映射缓存。重新开始关卡，并在操作发生前完成寻址和监控即可。

当前主界面没有为敌人表格和随机数表格提供单独的一键文件导出。需要对接其他程序时，可点击右上角“接口说明”，通过本地 WebSocket 获取实时数据。

## 十一、常见问题

### 1. 程序提示“未找到 adb.exe”

手动选择模拟器安装目录中的 `adb.exe`。MuMu 12 通常位于 `MuMuPlayer-12.0\shell\adb.exe`。如果更换了模拟器或移动了安装目录，删除程序旁的 `enemy_adb_config.json` 后重新选择。

### 2. `adb devices` 没有设备

确认模拟器已经完全启动，并在模拟器设置中开启 ADB 调试。其他模拟器可能需要先执行 `adb connect 127.0.0.1:<端口>`。

### 3. 提示“找不到游戏进程”

确认《明日方舟》已经启动，并且当前使用的是包名 `com.hypergryph.arknights` 的国服客户端。回到游戏主界面或重新进入关卡后再试。

### 4. 敌人扫描失败或提示未发现敌人

进入正常作战关卡，等待敌人出场后暂停，再点击“重新扫描”。扫描过程中不要让所有敌人退场，也不要结束关卡。

### 5. 扫描一直很慢

首次定位需要检查 Android GC 堆和运行时对象。保持模拟器与游戏运行，避免同时进行磁盘占用很高的任务。当前版本只支持设备侧 `memsrv v5` 内存通道；若该服务无法启动或不能读取 `/proc/<游戏PID>/mem`，程序会明确报错，不会回退到不稳定的旧 ADB 读取协议。

### 6. 时间或逻辑帧突然无效

通常是模拟器或游戏进程已经重启，原地址失效。使用自动寻址时可以关闭再重新勾选“启用自动寻址”；使用独立寻址工具时，重新点击“打开寻址工具”并完成扫描。

### 7. 操作记录中逻辑帧显示为“—”

说明时间/帧地址尚未配置，或该操作发生时还没有对应采样。先完成寻址，再重新开始关卡并记录。

### 8. “导出 JSON”提示仍有操作缺少逻辑帧

程序不会用不精确的数据强行导出。请在执行操作前完成时间寻址，并保持主程序持续运行。

### 9. 随机数区域没有新增记录

让干员攻击几次，或等待发生需要随机判定的技能、天赋、暴击或闪避。没有关键随机调用时序列不会消耗。

### 10. 换关卡后数据不再更新

旧关卡中的对象已经释放，地址链会失效。敌人监控和操作记录应重新扫描；随机数追踪通常会自动重定位，未恢复时手动停止并重新扫描。

### 11. 其他模拟器能显示时间，但敌人监控不能用

这是正常的兼容性差异。时间/帧数通过 Windows 读取模拟器宿主进程；敌人、操作和随机数功能需要模拟器内部的 root ADB、arm64 游戏进程和 `/proc/<pid>/mem` 读取权限。满足前者并不代表一定满足后者。

## 十二、推荐的新手使用顺序

每次准备记录一局战斗时，建议按以下顺序操作：

1. 启动模拟器和《明日方舟》；
2. 在“选择 ADB”中确认 `adb.exe` 和目标设备；
3. 开启自动寻址并确认时间与逻辑帧有效；若改用独立寻址工具，再以管理员身份重启主程序；
4. 进入目标关卡；
5. 点击“扫描关卡及操作”；
6. 有敌人出场后点击“开始扫描”；
7. 点击“扫描随机数”；
8. 等三个区域都进入监控状态后开始正式操作；
9. 战斗结束前导出操作记录 JSON。
