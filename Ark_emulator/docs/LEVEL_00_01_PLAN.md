# 0-1 完整模拟实施计划

0-1 仍是首个官方验收关卡。独立 `ark_sim` 已于 2026-10-02 重新完成模型验收：夜刀与克洛丝两人 11 击杀、零漏怪，连续运行、检查点续跑和完整输入回放的最终状态及 172,804 条事件摘要一致。证据见 [V2 模型验收记录](../ark_sim/validation/reports/v2_baseline_20261002.json)，当前模块与限制见 [V2 实现说明](V2_IMPLEMENTATION.md)。客户端逐帧准确性尚待实测。

下文保留阶段一的数据提取和实施计划。此前旧内核的模型结果属于历史记录，不能替代新版证据。

首个基准关卡由用户确定为 0-1，内部 ID 为 `level_main_00-01`。本文件限定首关的输入、依赖、迁移任务与验收，后续按 [需求](REQUIREMENTS.md) 和 [架构设计](ARCHITECTURE.md) 增加干员与关卡。

当前已完成首关模块化内核与模型回归：源石虫、士兵及其等待检查点和 DEF 覆盖已接入，夜刀、克洛丝、芬和芙蓉的精零配置已迁移。两人模型示例可 11 击杀、零漏怪清场，并精确重放。真实游戏对照尚未完成，目标客户端与热更版本仍需在真实验收样本中固定。运行和扩展方式见 [模块化实现说明](MODULAR_IMPLEMENTATION.md)。

SPAWN 数量来自当前原始波次的 count，不替代对实际客户端关卡版本的验证。STORY 若会阻塞、暂停或改变教程控制，需要在回放中显式表示其释放条件；展示敌人信息本身不能改变战斗数值。

## 首关所需机制

首关依赖至少包括地图与路线、波次和相关控制动作、敌人等级与覆盖、地面移动、基础敌人状态机、普通攻击 Ability、精确范围与目标选择、阻挡、属性与物理伤害、死亡与漏怪、费用、部署与撤退、再部署计时、快照和事件。加入克洛丝之后补远程弹道、对应技能与天赋，加入芬和芙蓉后分别补 SP 与费用效果、治疗和技能属性 Buff。

最终清单由关卡与选定配置的传递引用生成，并保存每一条依赖的来源。所有必要 Buff 与黑板值都在清单中解释，即便不是本关地图自带的 Buff。

## 验收场景

1. **输入完整**：地图、路线、波次、敌人定义、能力与引用齐全；关卡覆盖被应用；实际加载内容可列出。
2. **无人部署**：完整执行所有出怪与漏怪，核对路线、时间、防卫点变化和最终结算。当前数据只有 11 个固定敌人、防卫点为 20，不能直接把“无人部署”写成必然失败；结算预期以真实记录和规则确认。
3. **有效部署与交战**：固定操作序列完成关卡；核对目标、阻挡、攻击生效、伤害、费用与结束条件。只比较胜负不足以通过。
4. **非法操作**：不可部署地形、占用格、同一干员重复部署、费用不足、再部署冷却、非法技能和终局后命令都有明确结果，失败不改变战斗状态。
5. **状态转换**：敌人被阻挡、阻挡者撤退或死亡、攻击目标失效、敌人死亡和离场，不遗留阻挡与命中关系。
6. **暂停与单步**：暂停时 tick 不变；单步精确推进；后台请求不会与单步同时写状态。
7. **确定性**：相同内容摘要、养成、随机数初始状态与操作回放，关键状态和事件一致；加入概率天赋后必须核查随机数消耗。
8. **真实对照**：至少包含无部署和固定编队交战样本，并用针对性样本覆盖撤退、目标变化等机制；每个采样字段事先声明比较规则。

防卫点归零等首关自然过程未必能到达的边界，使用独立内核测试场景验证，不篡改官方关卡后仍称其为官方 0-1 对照。

## 下一关的准入

首关达到模型通过后可以并行准备下一关数据，但首个“完整模拟已验证”里程碑需要真实对照通过。新关卡先生成差异依赖清单：已有行为族直接复用，新增敌人、Buff、场地和调度机制分别补充，再跑首关回归。

新干员与新关卡分开推进，避免同时改变关卡、编队、数据版本与内核。每次扩展只提升经过验收的支持组合；不因能够加载而自动提升整个关卡或所有干员的状态。
